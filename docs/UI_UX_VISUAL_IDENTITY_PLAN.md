# خطة تجربة المستخدم والهوية البصرية — Cible Real Estate CRM

**الحالة:** خطة تفصيلية قبل التنفيذ؛ لا تتضمن تنفيذًا أو تغييرًا تشغيليًا.  
**تاريخ الإنشاء:** 2026-10-26  
**النطاق:** المشروع كاملًا: الصفحة العامة `/`، لوحة الإدارة، تسجيل الدخول وMFA، وكل مسارات Filament والقوائم والحالات التابعة لها، بلا استثناء.  
**مصادر الحقيقة:** `docs/PRD.md`، `docs/PERMISSIONS.md`، `docs/DECISIONS.md`، الكود الحالي، ومجلد `assets/`.

## 1. الهدف وحدود العمل

الغرض هو تحويل الواجهة الحالية إلى CRM عربي RTL متماسك يعكس هوية **Cible Real Estate / سيبل العقارية**، مع الحفاظ التام على قواعد العمل والبيانات والصلاحيات ومسارات الطلبات المعتمدة.

ينفذ العمل: تطبيق الأصول البصرية الصحيحة؛ بناء نظام تصميم صغير قابل لإعادة الاستخدام فوق Filament؛ إصلاح عيوب التخطيط والاستجابة؛ وتحسين قابلية المسح البصري للنماذج والجداول والطلبات والمتابعات، من دون تغيير الحقول أو شروطها أو تسلسل العمل.

لا يشمل العمل من دون موافقة لاحقة: تغيير قاعدة تجارية أو صلاحية أو مرحلة أو تحقق أو بنية بيانات؛ إضافة ميزات عقارية/محاسبية؛ استبدال Laravel أو Filament؛ وضع أصول خام أو بيانات حقيقية في مكان عام؛ أو وضع نمط زخرفي خلف جدول أو نموذج أو نص كثيف.

مرجع المتطلب: `PRD-015` و`NFR-001` يفرضان واجهة عربية RTL تعمل على سطح المكتب والهاتف؛ هذه الخطة تحدد طريقة الوفاء بهما ولا تعيد تفسيرهما.

## 2. الحالة الراهنة والأدلة

### 2.1 ما هو مثبت

| المجال | الحالة المثبتة | الأثر |
|---|---|---|
| الهوية | توجد نسخ SVG وPNG وJPG وPDF في `assets/`، منها شعار ذهبي/أحمر، شعار أسود، شعار أبيض، أيقونة، ونمط/خلفيات. | لا حاجة لاختراع شعار أو ألوان جديدة. |
| الألوان | ملفات SVG تثبت الذهبي `#C4A369` والأحمر `#AA2121`، وتظهر نسخة أخرى الأخضر الداكن `#183F3C`. | لا تعتمد أي درجة تشغيلية أو لون حالة قبل قياس التباين. |
| الخط | ملفات الهوية المحلية متاحة في `assets/fonts/`: `beIN Normal.ttf` و`Jost-Medium.ttf` (مع عائلة Jost إضافية). و`resources/css/app.css` ما زال يستخدم `Instrument Sans` الافتراضي. | خطا الهوية حُسما؛ يُحمّلان محليًا في مرحلة الثيم بدل أي تحميل خارجي. |
| Filament | `AdminPanelProvider` يعرّف `brandName` نصيًا و`Color::Amber` كلون أساسي ويعرض `FilamentInfoWidget`. | الشعار وfavicon والثيم والخط المؤسسي غير مربوطين. |
| البنية | Laravel + Filament + Tailwind/Vite. Filament يدعم `brandLogo()` و`favicon()` و`font()` و`viteTheme()`. | التنفيذ يتم عبر نقاط تمديد رسمية، لا اختراقات CSS عشوائية. |

### 2.2 عيوب مثبتة من لقطات المالك

سبب العيب التقني النهائي لا يُفترض قبل فحص DOM وCSS؛ لكن العيب المرئي نفسه مثبت.

| المعرف | الشاشة | الملاحظة | الأولوية | معيار الإغلاق |
|---|---|---|---|---|
| `UI-001` | الإطار العام | يظهر حرف `H` وهوية Filament الافتراضية بدل Cible، مع تذييل Filament. | حرجة للهوية | شعار وأيقونة وfavicon وتذييل مقصود فقط في كل نقطة دخول. |
| `UI-002` | لوحة التحكم | بطاقات المؤشرات تتدفق في شبكة غير متوازنة، وصف أخير/فراغ كبير بلا تسلسل هرمي. | عالية | شبكة محددة السلوك وعرض مؤشرات منظم بلا فراغ ميت. |
| `UI-003` | قائمة الموظفين | علاقة العنوان والزر والجدول ضعيفة، ومساحة الجدول والحواف والتمرير الداخلي تحتاج تدقيقًا. | عالية | تخطيط ثابت للعنوان والإجراءات والمرشحات والجدول بكل المقاسات المرجعية. |
| `UI-004` | عرض طلب الإيجار | بطاقات التفاصيل غير متوازنة وتنتج مساحة فارغة كبيرة وضعفًا في مسح البيانات. | عالية | مجموعات معلومات مقصودة ومحاذاة متسقة. |
| `UI-005` | إضافة طلب إيجار | شبكة الحقول والفراغات والتبديلات لا تقود المستخدم بوضوح. | عالية | نموذج متدرج ومحاذاة ثابتة واستجابة بلا تداخل أو فراغات ميتة. |
| `UI-006` | النظام كله | Amber والخط الافتراضي لا يعكسان الهوية، ولا نظام موحد للرموز والحالات. | عالية | tokens موثقة ومتسقة وتباين قابل للقياس. |
| `UI-007` | RTL والبيانات المختلطة | الأرقام والتواريخ والبريد والعملة قد تتأثر عند مزج العربية واللاتينية. | عالية | لا انعكاس أو قطع أو محاذاة خاطئة للنص أو الأرقام. |

كل كشف جديد يسجل كـ`UI-xxx` مع: الشاشة، حجم العرض، المتصفح، خطوات الإعادة، صورة قبل/بعد، السبب، الإصلاح، واختبار الإغلاق. لا يغلق العيب بعبارة «يبدو جيدًا» فقط.

## 3. مبادئ التصميم

1. العملية أولًا: الزخرفة لا تزاحم حقلًا أو تنبيهًا أو بيانات CRM.
2. RTL أصيل: الاتجاه والترتيب والأيقونات والجداول والتركيز تصمم للعربية أولًا، لا بعكس CSS جزئي.
3. هوية متزنة: الذهبي للعلامة والإجراء الأساسي، والأحمر لكَنَة محدودة؛ لا يصبح بديلًا دلاليًا للخطر أو التنبيه.
4. تسلسل واضح: عنوان الصفحة، الإجراء الأساسي، المهمة الحرجة، ثم التفاصيل.
5. اتساق: زر ومربع إدخال وبطاقة ووسم حالة واحدان في السلوك والشكل أينما تكررا.
6. وصولية مدمجة: WCAG AA كحد أدنى، تركيز لوحة مفاتيح واضح، ورسالة خطأ مرتبطة بحقلها.
7. استجابة دون فقدان: تتغير البنية في الهاتف، لا تختفي معلومات أو إجراءات.
8. لا تغير صامت في السلوك: كل تعديل مورد Filament يراجع معه التفويض والتحقق وLivewire والاختبارات.

## 4. نظام الهوية والتصميم

### 4.1 جرد الأصول وخريطة الاستخدام

في بداية التنفيذ ينشأ جرد موثق يشمل الاسم والمقاس والصيغة والشفافية واللون والاستعمال وحقوق الاستخدام. لا تُنسخ أو تُضغط أو تُحوّل الأصول في هذه الخطة.

| الأصل | الاستخدام المقترح | القيد |
|---|---|---|
| `Logo Cible Realestate1-01.svg`/الذهبي | الشعار الأساسي على الأسطح الفاتحة وتسجيل الدخول. | لا يستخدم favicon أو بحجم صغير جدًا. |
| `... BLACK-01.png` | بديل أحادي اللون للطباعة أو السطح الفاتح عند الضرورة. | لا يختلط مع الذهبي في الصفحة نفسها بلا سبب. |
| `... WHITE -01.png` | سطح داكن محدود أو دخول داكن إن اعتمد. | لا يوضع فوق صورة منخفضة التباين. |

| خلفيات `Dahab`/`Oily` | خيار واحد فقط بعد فحص التباين. | لا تنشر كلها ولا تستخدم من الاسم فقط. |

### 4.2 Design tokens

ينفذ الثيم بمتغيرات CSS/Tailwind موثقة ومقابلاتها في ألوان Filament، لا بقيم مبعثرة في Blade أو PHP. جدول القيم النهائي يوثق بعد اختبار التباين؛ القيم المثبتة حاليًا هي ألوان الأصل فقط.

| فئة الرمز | المقترح | ضابط الاستخدام |
|---|---|---|
| `brand.gold` | مشتق من `#C4A369` | CTA والتحديد والهوية؛ تتوفر درجة نص/حدود متوافقة. |
| `brand.red` | مشتق من `#AA2121` | لكَنَة هوية، لا يعني فشلًا تلقائيًا. |
| `brand.deep-green` | مشتق من `#183F3C` إذا ثبت اعتماده | يستعمل فقط بعد التباين ولا ينافس الذهبي. |
| `surface/text/border` | حياديات موثقة | سطح بيانات هادئ وقابل للقراءة. |
| `success/warning/danger/info` | ألوان دلالية مستقلة | تحمل نصًا/أيقونة/وصفًا ولا تستبدل بألوان الشعار. |
| المسافة/القياس | مقياس 4/8px، نصف قطر، ظل، ارتفاع تحكم | يمنع تفاوت البطاقات والفراغات الحالي. |
| الحركة | انتقالات قصيرة ودعم `prefers-reduced-motion` | لا حركة تعطل إدخال البيانات. |

قبل تثبيت الرموز ينتج تقرير تباين للنص والأزرار والوسوم وحالات hover/focus/disabled. اللون الذي لا يحقق AA كنص صغير يستخدم كخلفية أو حد لا كنص وحيد.

### 4.3 الطباعة واللغة والأيقونات

- تعتمد عائلة عربية مرخصة واحدة للمحتوى والعناوين، مع أوزان محدودة وfallback عربي سليم و`font-display` وpreload للضروري فقط.
- يحدد سلم صريح للعناوين ونص الحقول والمساعدة والجدول والوسم والرقم الإحصائي.
- يعزل البريد والهاتف والأكواد والعملات والتاريخ اتجاهيًا عند الحاجة، من دون تغيير القيم أو تنسيقها التجاري.
- تبقى Heroicons/Filament للوظائف إن كانت متسقة؛ تقاس الأيقونات حسب الموضع وتضاف تسمية/tooltip عند الغموض.
- تنشأ favicon ونسخ app icon من أيقونة Cible بعد اختبار 16/32/180/192/512px. لا يعرض PNG ضخم في الترويسة.

## 5. مواصفات الشاشات

### الصفحة العامة والإطار العام والدخول

- تعاد مراجعة صفحة Laravel العامة `/` باعتبارها نقطة دخول كاملة للهوية: الشعار، favicon، اللغة، العناوين، الأزرار، الخلفية/النمط، وحالات الرابط إلى لوحة الإدارة. لا يعني ذلك اختراع موقع تسويقي أو إضافة محتوى تجاري جديد؛ يحسن ما هو موجود ويطبّق الهوية على الصفحة الحالية وحالاتها.
- تدخل في الجرد كل صفحات النظام غير التابعة لمورد محدد، بما في ذلك صفحات الخطأ و404 و403 وأي صفحة مؤقتة أو فارغة أو landing موجودة، حتى لا تبقى هوية افتراضية في أي نقطة وصول.

- شعار كامل في الوضع الموسع وأيقونة في المنكمش؛ الاسم الوظيفي لا ينافس العلامة.
- مراجعة ترتيب مجموعات sidebar والحالة النشطة وفتح/طي القائمة والتنقل بلوحة المفاتيح.
- استبدال/إخفاء عناصر Filament الافتراضية غير المقصودة، ومنها الإصدار والروابط العامة، بتذييل Cible خفيف أو لا تذييل وفق قرار التنفيذ.
- توحيد رأس الصفحة وbreadcrumb: عنوان ثم وصف اختياري ثم الإجراء الأساسي، مع ترتيب RTL سليم.
- تكييف login/MFA ورسائل الخطأ والاسترداد والنجاح بصريًا فقط؛ لا تتغير آلية MFA أو إلزام المدير.

### لوحة التحكم

`OperationalRequestsOverview` ينتج حاليًا 7 بطاقات لكل قسم؛ لا تحذف الخطة أي مقياس. يفحص التنفيذ خيارات أعمدة widget ثم:

1. يقسم العرض إلى «تحتاج تدخلًا الآن»، «الطلبات»، و«ما بعد الصفقة» مع حفظ القيم والتعريفات.
2. يعتمد شبكة متوقعة: عمود للهاتف، اثنان للوحة الصغيرة، وثلاثة أو أربعة بحسب عرض المحتوى على سطح المكتب.
3. يبرز المتابعة المتأخرة من دون جعل الصفر أو الحالة العادية حمراء.
4. يراجع AccountWidget وأي widget معلومات عام ويزيل المظهر الافتراضي غير المقصود بلا حذف بيانات أو تغيير صلاحيات.

### القوائم والجداول

يشمل ذلك الموظفين والعملاء والطلبات والوسطاء ومصادر الوصول والمناطق وأسباب الإغلاق وسجل التدقيق:

- قالب واحد: رأس، إجراء أساسي وثانوي، مرشحات/بحث، جدول، ترقيم، وحالة فارغة.
- أعمدة RTL بحسب مهمة الموظف، وعرض مناسب للاسم والحالة والتاريخ والإجراءات؛ لا انزلاق أفقي غير مبرر على سطح المكتب.
- للهاتف تستخدم الأولويات/التفاصيل المتاحة في Filament بدل تصغير الخط حتى يفقد القراءة.
- أزرار الإجراءات مفهومة وتملك مساحة نقر مناسبة؛ الخطير منفصل ومؤكد.
- تدقيق sticky header والتمرير وحاوية المحتوى لحل التمرير الداخلي المربك المرصود في قائمة الموظفين.

### إنشاء وتحرير وعرض الطلبات

- يعاد ترتيب الأقسام بصريًا: الأطراف → الموقع والمتابعة → متطلبات القسم → الميزانية والمتطلبات → ملاحظات/إغلاق شرطي.
- يبقى مخطط الحقول ومصدر شروطها (`Section::make` وغيرها) كما هو؛ تضبط spans والأعمدة والفواصل فقط بعد اختبار كل dependency وحقل شرطي.
- تسمية ثابتة، مساعدة موجزة، إلزام واضح، ورسالة تحقق أسفل الحقل ذاته.
- تعرض الميزانية والعملات والمدد كبيانات مالية متسقة؛ تبقى ميزانيات الإيجار الشهرية وقواعد الإيجار المعتمدة كما هي.
- لا تفقد التبديلات و«أخرى» والحقول الشرطية القيمة أو التركيز عند الاستجابة أو إعادة رندر Livewire.
- توضع أزرار الحفظ والإلغاء و«إضافة وبدء إضافة المزيد» باستقرار عند طول النموذج، من دون تغيير أسمائها أو آثارها.
- يعاد بناء عرض الطلب/الصفقة/aftercare إلى شبكة تفاصيل: الحالة والمتابعة، الأطراف والموقع، المتطلبات والميزانية، ثم الإغلاق/الصفقة عند وجودها. تعالج المساحة الفارغة بضبط grid/span لا بحشو ارتفاع أو محتوى وهمي.

### الشاشات الدقيقة

تراجع أيضًا: إنشاء/تعديل الموظف، الأرشفة/الاستعادة، إعادة التعيين، سجل التدقيق، النوافذ المنبثقة، المرشحات والاختيارات والعلاقات، التصدير إن وجد، منع الوصول، التحقق، لا نتائج، التحميل، والنصوص الطويلة.

## 7. الاختبار وضمان الجودة

### مصفوفة العرض

الحد الأدنى: 360px و390px (هاتف)، 768px (لوحي عمودي)، 1024px (لوحي أفقي/لابتوب صغير)، 1280px و1440px (سطح مكتب). Chrome وFirefox حديثان على Windows، وSafari/iOS إن توفرت أجهزة العمل؛ تكبير 100% واتجاه RTL.

### السيناريوهات الحرجة

1. دخول مدير الشركة وإتمام MFA والتنقل في القسمين.
2. دخول موظف إيجار وموظف إعادة بيع، ثم مقارنة القائمة والبحث والاختيارات والروابط المباشرة.
3. إنشاء/تعديل/عرض طلب إيجار وإعادة بيع، بما فيه «أخرى» والشرطية والميزانيات والعملة والمواعيد وأخطاء التحقق.
4. إغلاق ناجح وغير ناجح، صفقة يدوية مؤهلة، متابعة وaftercare، توقف/استئناف، أرشفة/استعادة، وإعادة تعيين ضمن الصلاحية.
5. قائمة طويلة/فارغة، اسم طويل، ملاحظة متعددة الأسطر، رقم مصري/دولي، EGP/USD، ورسالة خطأ طويلة.
6. لوحة المفاتيح فقط: Tab/Shift+Tab/Esc/Enter والتركيز وmodal وترتيب القراءة RTL.

### الدليل المطلوب

- بصري: صور قبل/بعد بالعرض نفسه، لا مقارنة انطباعية فقط.
- وظيفي: `php artisan test` والاختبارات المركزة لمسارات Filament المتأثرة، بلا حذف اختبار للوصول إلى نتيجة خضراء.
- بناء: `npm run build` وPint للملفات المعدلة وفق الإعداد الحالي.
- إتاحة: تباين وتركيز وتسميات وحجم لمس، وأداة آلية فقط إذا لم توسع النطاق بلا حاجة.
- أداء: حجم الشعار/الخطوط/الصور وعدم تحميل أصل ضخم أو حجب أول عرض.

تحدث `docs/ACCEPTANCE_TESTS.md` بنتائج منفذة ودليل محدد فقط: آلي/يدوي، تاريخ، بيئة، ونتيجة.

## 9. قرارات الهوية المعتمدة — 2026-10-26

| القرار | الاعتماد | أثر التنفيذ |
|---|---|---|
| نطاق العمل | المشروع كله: الصفحة العامة `/`، لوحة `/admin`، تسجيل الدخول وMFA، وكل القوائم والصفحات والحالات بلا استثناء. | يطبق التصميم على كل نقطة دخول قائمة، من دون اختراع ميزات أو محتوى تسويقي جديد. |

## 10. تعريف الاكتمال

لا تعد المرحلة مكتملة إلا إذا:

- لا تبقى هوية Filament الافتراضية أو Amber أو `H` placeholder أو تذييل غير مقصود في المسارات المشمولة.
- ينجح كل سيناريو متأثر مع صلاحياته واختباراته ذات الصلة.
- تغلق `UI-001` إلى `UI-007` بدليل قبل/بعد وعلى المقاسات المعتمدة، أو يسجل استثناء وافق عليه المالك.
- لا مشكلة P0/P1 معروفة في RTL أو لوحة المفاتيح أو نموذج الطلب أو عزل الأقسام.
- توثق الأصول والخطوط وتراخيصها ومواقعها النهائية، وتحدث الوثائق بالحالة الفعلية فقط.

## 11. البداية الفعلية

بعد حسم القرارات الأربع تبدأ المرحلة 0 ثم 1، ويعرض سجل العيوب وخريطة الأصول وwireframes/نماذج الشاشات المقترحة للاعتماد قبل إدخال CSS أو تعديل موارد Filament. بهذا تصبح معالجة محاذاة البطاقات والفراغات وغيرها من اللقطات عملًا مضبوطًا وقابلًا للقياس، لا تعديلات متفرقة.
