# Cible Real Estate CRM — سياق المشروع

**الحالة:** مرجع سياقي معتمد في نطاقه؛ التفاصيل غير المحسومة محالة إلى [`DECISIONS.md`](./DECISIONS.md).  
**آخر تحديث:** 2026-10-22

## 1. الغرض

Cible هو نظام CRM داخلي لشركة Cible Real Estate لإدارة العلاقة مع العملاء وطلباتهم ومتابعاتهم وترشيحاتهم ومعايناتهم وصفقاتهم، ثم استمرار تلك العلاقة بعد إغلاق الصفقة.

الهدف التشغيلي هو تقليل الفرص الضائعة، وتنظيم بيانات العملاء داخل كل قسم، وضمان وجود مسؤول ومتابعة قادمة لكل طلب نشط، وإعطاء المدير رؤية موثوقة لحالة العمل في قسمي الإيجار وإعادة البيع.

## 2. النطاق المعتمد

### 2.1 إدارة العملاء

- لكل قسم سجلات عملاء مستقلة، ولا يوجد ملف عميل مشترك بين الإيجار وإعادة البيع (`D-020`).
- إذا تعامل نفس الشخص مع القسمين، يُنشأ سجل عميل منفصل في كل قسم، ويجوز أن يختلف محتوى السجلين.
- داخل القسم، العميل وطلب العميل والصفقة كيانات منفصلة، والعلاقة مع العميل لا تبدأ من جديد مع كل صفقة.
- تعديل بيانات العميل في قسم لا يحدّث سجل القسم الآخر تلقائيًا.
- لا يوجد deduplication أو linking أو synchronization أو بحث عميل مشترك تلقائي بين القسمين.

### 2.2 الطلبات والصفقات

- الطلب يمثل احتياج العميل ودورة العمل الخاصة به.
- الصفقة كيان مستقل يرتبط بالطلب، ولا تُعامَل كأنها مجرد تغيير في حالة الطلب.
- الترشيحات والمعاينات بيانات مرتبطة بسياق الطلب، ولا تتحول إلى كتالوج عقاري.
- لكل طلب نشط مسؤول ومتابعة قادمة بتاريخ محدد.

### 2.3 الفصل بين الإيجار وإعادة البيع

- للإيجار وإعادة البيع مساران تشغيليان منفصلان، ولكل منهما سجلات عملاء مستقلة.
- بيانات العميل وملاحظاته وطلباته ومراحل عمله ومتابعاته وشاشاته وتقاريره وصفقاته وaftercare الخاصة به لا تُخلط بين القسمين.
- لا يوجد ملف عميل مشترك، ولا بحث عميل موحّد يدمج أو يربط سجلات القسمين (`D-020`).
- موظف الإيجار لا يصل إلى سجلات إعادة البيع، وموظف إعادة البيع لا يصل إلى سجلات الإيجار.

### 2.4 استمرار العلاقة بعد الصفقة

- استمرار العلاقة بعد إغلاق الصفقة قرار معتمد، وليس مجرد ملاحظات في ملف العميل.
- الغرض هو الثقة والاحتفاظ بالعميل والفرص المستقبلية والإحالات.
- أمثلة الأنشطة المذكورة (تواصل دوري، تحيات الجمعة، محتوى تعليمي عن السوق العقاري المصري، عرض خدمات مناسبة) أمثلة وليست التزامًا بجدول أو قناة أو أتمتة.
- استمرار العلاقة بعد الصفقة يحدث داخل القسم المعني ويرتبط بسجل العميل الخاص به؛ لا توجد علاقة aftercare مشتركة بين القسمين.
- تفاصيل التوقيت والقنوات والموافقات والأتمتة والمسؤول داخل القسم ما زالت غير محسومة (`Q-007`).

## 3. الاستثناءات الصريحة

خارج نطاق Cible CRM في الإصدار الأول، وما لم يُعتمد لاحقًا بشكل صريح:

- نظام مستقل لعرض أو إدارة القوائم العقارية أو كتالوج الوحدات.
- إدارة مخزون العقارات أو إدارة الممتلكات.
- إدارة الصيانة.
- المحاسبة أو تحصيل الأموال أو إدارة العقود المالية.
- أي تكامل خارجي غير معتمد.

بيانات الوحدة أو العقار تُسجل فقط بالقدر اللازم لدعم طلب أو ترشيح أو معاينة أو صفقة. لا تُنشأ شاشة بحث أو إدارة لقاعدة ملاك أو وحدات.

## 4. حدود بيانات الوحدة والمالك

- بيانات المالك البائع تُحفظ داخل سياق الصفقة عند الحاجة، ولا تُنشئ قاعدة بيانات مستقلة للملاك.
- الوحدة قد تكون مسجلة في تطبيق Listing خارجي، وقد لا تكون. يمكن تسجيل كود الوحدة فقط عند الحاجة (`D-016`)، بدون تكامل في الإصدار الأول. يصف المصدر `S-013` الكود بأنه رقمي؛ تفاصيل بيانات الوحدة وتأكيد شكل الكود تبقى `Q-005`.
- الحد الأدنى الدقيق لحقول الوحدة والمالك لم يُحسم بعد، وهو سؤال مفتوح `Q-005` في [`DECISIONS.md`](./DECISIONS.md). يشمل السؤال ما إذا كان يلزم حقل يحدد وجود الوحدة في تطبيق Listing قبل تسجيل كودها.

## 5. الأدوار والأقسام

الأدوار المعتمدة حاليًا:

| الدور | النطاق |
| --- | --- |
| موظف إيجار | سجلات عملاء الإيجار وطلبات الإيجار وبياناتها التشغيلية فقط |
| موظف إعادة بيع | سجلات عملاء إعادة البيع وطلبات إعادة البيع وبياناتها التشغيلية فقط |
| مدير الشركة | قراءة/عرض قسمي الإيجار وإعادة البيع وبياناتهما التشغيلية، دون بحث عميل موحّد أو دمج للسجلات |

هذا لا يحدد بعد ما إذا كان يمكن تعيين الموظف في القسمين أم لا؛ هذه نقطة `Q-008`. كما أن حقول سجل العميل المطلوبة داخل كل قسم لم تُحسم بعد (`Q-001`). صلاحيات المدير في الإنشاء والتعديل والحذف والتجاوز وإعادة التعيين لم تُحسم (`Q-018`)؛ `D-020` يثبت قراءة القسمين فقط.

تصف الملاحظات المصدرية `S-013` تنظيم استقبال طلبات الإيجار بواسطة الموظف المسؤول، وتقترح عدم منح المندوب الميداني حسابًا حاليًا. لا يُعد وصف الموظف بأنه «Admin» اعتمادًا لصلاحيات إدارة، ولا تحسم هذه الملاحظات وحدها منح حساب للمندوب أو صلاحيات الكتابة.

## 6. مسؤولية الطلب ومصدر الوصول

- الموظف الذي يستقبل العميل يكون مسؤولًا عن طلبه مبدئيًا.
- مصدر وصول العميل أو القناة التي جاء منها منفصل عن مسؤولية الطلب، وقد يكون موظفًا آخر.
- الوسيط العقاري، إن وُجد، مفهوم منفصل عن مصدر الوصول وعن مسؤولية الطلب. اعتباره كيانًا مستقلًا متطلب مصدري (`S-003`) لم يُعتمد كقرار مستقل في هذه المراجعة.

لا تُستخدم بيانات المصدر كبديل عن مسؤول الطلب، ولا تُستخدم مسؤولية الطلب كبديل عن تسجيل المصدر.

## 7. التقنية المعتمدة

- Laravel.
- MySQL.
- Filament.
- تطبيق واحد وقاعدة MySQL واحدة؛ لا تطبيقات أو سيرفرات أو قواعد فيزيائية منفصلة دون اعتماد لاحق.
- واجهة عربية RTL.
- استخدام متجاوب على سطح المكتب والهاتف.

هذه التقنية معتمدة كاتجاه تنفيذي. لا يوجد تطبيق أو مخطط قاعدة بيانات منفذ بعد.

### 7.1 سياق تشغيلي موثق من المصدر

المستند `02` يوثق بيئة تشغيل محلية على Apache/PHP باستخدام XAMPP، خلف Cloudflare Tunnel وZero Trust Access، مع تسجيل دخول مستقل داخل التطبيق وأدوار موظف/مدير. هذا سياق `S — متطلب مصدري` لم يُعد اعتماده ضمن هذه المراجعة، ويجب تثبيته قبل تصميم النشر. لا يُفهم منه أن التطبيق الحالي منفذ أو مؤمن فعليًا.

## 8. المؤشرات العامة للنجاح

النجاح يُقاس بتحسن العمل اليومي، لا بعدد الشاشات:

- انخفاض الطلبات النشطة بلا متابعة قادمة.
- وضوح مسؤول كل طلب.
- اكتمال نتائج المعاينات والإغلاقات (متطلب مصدري `S-012`، وليس إلزامًا معتمدًا بعد).
- انضباط متابعات ما بعد الصفقة.
- قدرة المدير على رؤية ما يحتاج تدخلًا دون سؤال كل موظف.

الأهداف الرقمية النهائية لم تُعتمد، وتظل مقترحات في المستند المصدر.

## 9. Excel وWhatsApp

ضمن الإصدار الأول (`D-021`، `D-022`، `D-023`):

- استيراد عملاء القسم بإنشاء سجلات جديدة فقط، وتصدير العملاء والطلبات الظاهرة داخل القسم.
- زر فتح محادثة WhatsApp إذا كانت بيانات الاتصال متاحة، مع إمكانية تسجيل التواصل داخل CRM.

خارج النطاق المعتمد حاليًا:

- تكامل WhatsApp Business API، وإرسال/استقبال آلي، ومزامنة المحادثات.
- اعتبار ملف Excel مصدر حقيقة بديلًا عن قاعدة CRM، أو مزامنة مستمرة معه.
- استيراد طلبات أو أنشطة أو صفقات أو عمولات، أو تصدير صفقات/عمولات/تفريغ أنشطة، أو تحديث عملاء بالمطابقة عبر Excel.

الحقول والقوالب تبقى `Q-024` بعد `Q-001`/`Q-004`. صيغة `.xlsx` والاستيراد الجزئي والتحقق والتقرير وإعادة المحاولة معتمدة في `D-024`؛ التفاصيل المتبقية وحدود الملف الرقمية `Q-025`. WhatsApp يبقى `Q-026`–`Q-027`. عزل القسمين نافذ على الاستيراد والتصدير والزر وتسجيل التواصل.
